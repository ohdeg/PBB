# Tempori 보관함 및 연습 상태 동기화 구현 계획

> 실행 시 executing-plans를 적용한다. 구현 담당자 한 명이 순차 구현하고 별도 검토 후 재검증한다. 현재 문서는 계획이며 구현/배포하지 않는다.

**Goal:** 간단한 악보 업로드 UI와 악보별 계정 업로드를 제공하고 필기·템포·연습 위치를 같은 계정의 기기 사이에서 복원한다.
**Architecture:** 원본은 기존 비공개 R2, 사용자 연습 상태는 MySQL의 버전 관리 문서로 저장한다. 클라이언트는 IndexedDB에 먼저 기록하고 계정·악보별 대기열로 서버와 동기화한다.
**Tech Stack:** 기존 React/TypeScript, IndexedDB, Spring/JPA, MySQL, R2.
**Spec:** 이 대화의 2026-11-02 사용자 요청. 이전 페이지/제스처/클라우드 기능은 유지한다.

## 현재 코드에서 확인한 사항

- `saveTempori`는 이미 비로그인이면 로컬 저장 후 반환한다. 이 동작을 회귀 테스트로 고정한다.
- 로그인 목록은 계정 소유 로컬 초안과 서버 악보만 합쳐서 비로그인 기기 악보가 빠진다.
- 현재 일괄 이전 모달과 실패 악보 재시도 버튼이 따로 있다.
- 페이지 필기는 localStorage의 악보/레이아웃 키, 다른 모드 필기도 별도 구조를 사용한다. BPM은 기기 공통 키를 읽는다.
- 이전 계획 문서 디렉터리 `docs/superpowers`는 현재 ignore 대상이다. 프로젝트 지침에 따라 이 비ignored `plans` 경로에 저장한다.

## 제품 동작 및 수용 조건

1. 상단 버튼을 기존 아이콘 체계의 업로드 아이콘 + `악보 업로드`로 변경한다. PDF/MXL/MusicXML/XML 허용은 유지한다. 아이콘은 장식용 aria-hidden, 버튼 이름은 텍스트로 제공한다.
2. `새 악보는 이 기기(IndexedDB)에 저장됩니다. 계정 연동 없이 바로 연습할 수 있습니다.` 설명을 제거한다. 필기가 기기에만 저장된다는 현재 설명도 수정/제거한다. 형식 안내는 파일 선택 주변의 짧은 지원 형식 안내로 남긴다.
3. 비로그인: 원본·필기·연습 상태는 기기에만 저장한다. 악보/상태 API 호출 0회. 계정 업로드 버튼은 숨긴다.
4. 로그인 중 새 파일: 기존대로 기기 저장 후 자동 서버 업로드. 실패해도 기기 원본과 상태를 유지한다.
5. 로그인 보관함: 현재 계정 서버 악보 + 현재 계정 미업로드 초안 + 비로그인 기기 악보를 보여준다. 다른 계정의 초안/캐시는 노출하지 않는다. 로그인 자체로 비로그인 악보를 자동 업로드하지 않는다.
6. 일괄 `이 기기의 악보를 계정에 저장` 버튼과 모달 진입을 제거한다. 미업로드 행에만 `업로드` + 아이콘, 실패 시 `다시 업로드`, 진행 중 비활성 `업로드 중…`을 보여준다. 저장된 행은 버튼 없이 `계정 저장됨`. 서버 목록 조회 실패를 미업로드로 오판하지 않는다.
7. 업로드는 기존 멱등 키와 로컬→서버 ID 매핑을 재사용한다. 같은 원본의 로컬/서버 이중 표시를 제거하되 다른 제목으로 의도적으로 등록한 악보를 파일 해시만으로 합치지 않는다.
8. 같은 계정으로 다른 기기에서 서버 악보를 열면 마지막 동기화된 필기·악보별 템포·연습 위치를 복원한다. 재생은 자동 시작하지 않는다.

### 모바일·태블릿 스와이프 / 컴퓨터 쓰리닷 메뉴 (추가 요청 반영)

- 첨부 화면처럼 행 옆의 삭제/재시도 버튼이 제목 영역을 좁히지 않도록 모바일 기본 상태에서는 액션을 접고 악보 카드가 행 전체 너비를 사용한다. 제목은 최대 두 줄, 상태/아티스트는 각 한 줄 말줄임으로 표시하고 전체 제목은 접근 가능한 이름으로 제공한다.
- 모바일·태블릿 모두 기본 액션을 접고 왼쪽 스와이프로 같은 메뉴를 펼친다. 컴퓨터는 카드 우상단 `⋯` 클릭으로 메뉴를 연다. 모든 크기에서 삭제/업로드 버튼을 행 옆에 상시 배치하지 않는다. 레이아웃은 기존 breakpoint를 재사용하되 제스처 허용은 화면 너비만으로 결정하지 않는다. touch pointer에서만 스와이프를 처리하고 mouse/trackpad 드래그는 처리하지 않는다. 터치 가능한 컴퓨터는 터치 입력 시 같은 제스처를 사용할 수 있다.
- 카드를 왼쪽으로 밀면 오른쪽 뒤편에 메뉴가 드러난다. 드러난 메뉴의 화면상 왼쪽→오른쪽 순서는 **삭제 → 업로드**. 서버 저장 완료/비로그인은 삭제만, 로그인 미업로드는 삭제+업로드, 실패는 삭제+다시 업로드. 원본 업로드 중에는 삭제와 중복 업로드를 비활성화한다.
- 메뉴는 별도 레이어로 배치하고 카드에 transform을 적용한다. 버튼 때문에 카드 본문 폭을 줄이거나 페이지 전체에 가로 스크롤이 생기지 않게 한다. 액션 터치 영역은 최소 44×44 CSS px, 두 버튼 전체 너비는 카드 너비 이내로 제한한다.
- 수평 이동 12px 이상이고 가로 이동이 세로의 1.5배 이상일 때만 드래그로 판정한다. pointerup 시 메뉴 폭의 35% 이상 열렸으면 펼치고 나머지는 닫는다. 수직 스크롤/pinch는 브라우저에 맡기고 pointercancel은 안전하게 정리한다. 드래그 이후 click으로 악보가 열리지 않게 한다.
- 한 번에 한 행만 펼친다. 오른쪽 스와이프, 카드 탭, 바깥 탭, Escape로 닫는다. 열린 카드 첫 탭은 닫기만 수행한다. 화면 크기/계정/목록 변경 시 열린 상태를 초기화한다.
- 스와이프만으로 삭제/업로드를 실행하지 않는다. 삭제는 기존 확인창을 유지하고 기기 삭제/계정 삭제의 범위를 명시한다. 업로드 완료 후 버튼을 제거하고 메뉴를 닫는다. 실패 시 재시도 가능한 상태와 오류 안내를 유지한다.
- 모든 기기에서 카드 내부 우상단에 작은 `⋯` 버튼(접근 가능한 이름 `악보 메뉴`, aria-expanded)을 제공한다. 모바일·태블릿에서는 스와이프와 쓰리닷을 동시에 사용할 수 있는 선택적 입력 방식이며 별도 켜기/끄기 설정은 추가하지 않는다. 모바일·태블릿의 쓰리닷은 스와이프와 동일한 액션 영역을 펼친다. 컴퓨터에서는 버튼 옆 팝오버로 `삭제 → 업로드`를 위에서 아래 순서로 제공하며 카드 폭을 변경하지 않는다. 같은 액션/권한/진행 상태를 공유하고 중복 메뉴는 열지 않는다.
- 쓰리닷은 독립 버튼으로 구성해 악보 링크 안에 중첩하지 않는다. 숨겨진 액션은 탭/스크린리더 순서에서 제외한다. Escape로 닫을 때 메뉴 버튼으로 포커스를 복원하고 바깥 클릭으로 닫을 때는 클릭 대상의 포커스를 빼앗지 않는다. 모션 감소 설정을 존중한다.

## 동기화 데이터와 충돌 정책

### 로컬 원본 우선 열기 및 다운로드 실패 안내

- 서버에만 원본이 있으면 다운로드 → SHA256/크기 검증 → IndexedDB 저장 완료 → 저장된 로컬 원본으로 열기 순서를 따른다. 로컬 저장 완료 전 악보 뷰어로 진입하지 않는다.
- 서버·로컬 모두 있으면 검증된 로컬 원본으로 열고 필기·연습 템포·연습 위치의 서버 revision을 확인해 변경분만 동기화한다. 원본 해시가 같으면 원본을 다시 다운로드하지 않는다. 미전송 로컬 수정에는 기존 충돌 정책을 적용한다.
- 저장 공간 부족이 확인된 경우 정확히 **`저장공간이 부족해 다운로드에 실패했습니다`**를 표시한다. IndexedDB 저장의 QuotaExceededError 등 확인 가능한 원인으로 구분하고, 모든 저장 예외를 공간 부족으로 추정하지 않는다.
- 그 밖의 다운로드·무결성 검증·로컬 저장 실패는 정확히 **`오류가 발생하여 다운로드에 실패하였습니다`**를 표시한다.
- 실패하면 메모리 원본으로 대신 열지 않는다. 실패 안내와 재시도 버튼을 제공하며 기존 정상 캐시는 보존한다. 원본과 완료 메타데이터는 원자적으로 저장하여 실패한 파일을 정상 다운로드로 표시하지 않는다. 계정 변경/사용자 취소는 다운로드 오류로 표시하지 않는다.
- 이 문구는 원본 다운로드 및 로컬 저장 실패에 적용한다. 유효한 로컬 원본을 연 뒤 발생한 필기/연습 상태 동기화 실패는 별도 동기화 안내를 사용하고 다운로드 실패로 표현하지 않는다.

- 원본 식별자는 서버 scoreId + original SHA256. 로컬 별칭을 매핑하고 계정 ID를 모든 로컬 상태/대기열 키에 포함한다.
- `practice` 문서: BPM, 마디별 tempoChanges, 연습 범위, 반복 여부. 현재 타입의 유효성 검사/범위를 재사용한다.
- `position` 문서: MusicXML은 물리적 마디 인덱스와 마디 내 진행 비율, PDF는 0-based 페이지와 페이지 내 정규화 위치. 화면 픽셀 좌표는 저장하지 않는다. PDF에는 BPM 기반 진행을 추가하지 않는다.
- `annotations:<mode>:<layoutKey>` 문서: 모드별 기존 필기 문서와 스키마 버전, 원본 해시, 레이아웃/조옮김 정보. 임의로 서로 다른 모드 좌표를 변환하지 않는다. 호환되지 않는 필기는 보존하고 맞는 레이아웃에서만 표시한다. 여러 줄 모드도 렌더러 버전·줄당 마디·조옮김 등 좌표에 영향을 주는 조건을 키에 포함한다.
- 보기 모드·확대율·카메라 권한/설정·도구 패널은 기기 설정으로 유지한다. 위치 복원을 위해 사용자의 화면 설정을 강제로 바꾸지 않는다.
- 서버 문서 단위 revision과 compare-and-set 적용. 클라이언트 시각만으로 승자를 정하지 않는다. 요청은 `{baseRevision, mutationId, schemaVersion, payload}`. 성공 응답은 `{revision, updatedAt, payload}`; 충돌은 409와 최신 문서.
- 서로 다른 문서는 독립 동기화. 같은 문서 충돌은 양쪽 사본을 기기에 보존하고 `이 기기 내용 사용 / 서버 내용 사용`으로 해결한다. 필기 전체 삭제도 동일한 버전 검증을 거쳐 오래된 기기의 필기 부활을 막는다. 임의 last-write-wins는 사용하지 않는다.
- 수정은 로컬에 먼저 기록하고 durable outbox에 저장한다. 필기 완료/설정 적용 후 1초 debounce, 재생 위치는 변경이 있을 때 최대 5초에 1회 및 일시정지/나가기 시 기록한다. 종료 시 네트워크 성공에 의존하지 않고 다음 접속에 재시도한다.
- 열기·온라인 복귀·탭 복귀 시 서버 확인. 열린 악보는 visible 상태에서 30초마다 확인하되 재생/필기 중에는 화면을 이동시키거나 편집 상태를 교체하지 않는다. 깨끗한 상태에서 적용하거나 갱신 안내를 제공한다.
- 로컬 미업로드 악보는 상태도 로컬 전용. 원본 업로드 성공 후 상태를 초기 동기화한다. 원본 성공/상태 실패는 구분해서 상태만 재시도하며 원본을 다시 올리지 않는다.
- 계정 변경/로그아웃은 진행 요청 중단 및 늦은 응답 폐기. 대기열은 이전 계정에 남기고 새 계정으로 전달하지 않는다. 비로그인 사본과 계정 사본의 편집은 업로드 이후 분리한다.

## 서버 인터페이스·저장소

- 새 `TemporiStateController`, `TemporiStateService`, `TemporiScoreState`, repository를 기존 domain/tempori에 추가.
- `GET /api/v1/tempori/{scoreId}/state`: 연습/위치/필기 문서별 revision 목록 및 제한된 페이지네이션. 필기는 필요 레이아웃만 요청.
- `GET /api/v1/tempori/{scoreId}/state/{documentKey}` 및 `PUT` 동일 경로. key는 안전한 인코딩/길이 제한 및 허용 종류 검증. GET/PUT 모두 기존 immutable owner 인증 및 READY 악보 소유권 검사.
- `tempori_score_states`: score_id, owner_id, document_key, schema_version, revision, payload(JSON), updated_at; unique(score_id, document_key). 멱등 재전송은 mutation ID와 payload hash를 함께 저장/검증하는 별도 기록으로 처리한다. 상태 변경과 멱등 기록은 한 트랜잭션.
- 초기 한도: 필기 문서 UTF-8 JSON 2MiB, practice/position 각각 64KiB, 악보 전체 상태 20MiB. 프론트/서버 동일 제한, 초과는 413 및 로컬 보존 안내. 좌표·색상·선 개수/점 개수·숫자 finite 검증, 스키마 버전 allowlist.
- quota와 악보 삭제 경쟁은 악보 행 잠금으로 직렬화. 삭제 후 상태 PUT은 거절하며 서버 상태와 멱등 기록도 정리한다. 계정 삭제 정리 경로에 포함한다. 반환은 private/no-store. R2 공개 설정이나 프론트 자격증명 추가 없음.
- 새 SQL `infra/mysql/migrations/20261102_tempori_score_states.sql`, 신규 설치 init SQL 및 배포 안내 갱신. 실행 스크립트 `scripts/migrate-tempori-prod.sh`는 원본 테이블→상태 테이블 순서, 오류 시 중단, 성공 확인. 실제 환경 파일을 에이전트가 읽거나 실행하지 않는다. 사용자가 운영에서 실행할 때 Compose가 주입한 MySQL 환경을 사용한다.
