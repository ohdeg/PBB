# Tempori 모든 기기 한 줄·여러 줄 보기 계획

**상태:** 검토·계획만. 제품 코드 변경 및 배포 없음.
**요구:** 휴대폰·태블릿·데스크톱 모두에서 `한 줄 / 여러 줄`을 선택할 수 있다. 저장된 선택이 없을 때만 휴대폰은 한 줄, 태블릿·데스크톱·판별 불명 기기는 여러 줄을 기본값으로 사용한다. 기기 회전을 강제하지 않는다.
**구현 절차:** writing-plans → 독립 계획 리뷰 → 승인 후 executing-plans/TDD → 독립 코드 리뷰 → 재검증. 한 명이 구현하며 별도 커밋/배포는 요청 시 수행한다.

## 확인된 근거

- `components/OsmdViewer.tsx`는 `renderSingleHorizontalStaffline:false`를 사용한다. 설치된 OSMD 선언은 이 옵션을 `load()` 전에 설정해야 한다고 명시한다. 보기 변경은 재로드/재렌더 revision을 거쳐야 한다.
- `constants/temporiLayout.ts`와 `utils/musicXml.ts`가 줄당 마디 수 및 XML 줄바꿈을 강제한다. 한 줄 모드에서 해당 규칙·줌 축소 반복을 우회해야 한다. 피아노 양손 보표는 그대로 한 시스템에 유지한다.
- `TemporiAutoScroller.tsx`/`scrollAnchor.ts`는 세로 document 스크롤을 사용한다. 한 줄 모드는 내부 컨테이너 `scrollLeft`가 필요하다.
- `measureTiming.ts`는 컨테이너 DOM 좌표를 사용한다. viewport와 content 좌표를 구분하고 앞선 마디 래퍼 보정을 보존해야 한다.
- `TemporiAnnotationLayer.tsx`는 전체 악보 크기의 canvas 두 장과 정규화된 전체 화면 좌표를 사용한다. 긴 가로 캔버스는 메모리/최대 크기 위험이 있고 기존 필기는 재배치할 수 없다.
- `platform.ts`에는 iPad 판별만 있다. 기기 판별은 최초 기본값에만 사용하고 기능 접근은 제한하지 않는다. 작은 브라우저 창을 휴대폰으로 오인하지 않는 정책이 필요하다.

## 사용자 경험 결정

1. 모든 기기에서 두 보기의 기능을 동일하게 제공한다. 유효한 저장 선택이 없는 경우 확실한 휴대폰은 한 줄, 태블릿·PC·판별 불명 기기는 여러 줄로 시작한다. 단순 창 너비만으로 분류하지 않는다. iPhone/iPod 및 Android Mobile 신호, iPad 예외, 터치 특성을 조합하고 결과를 순수 함수로 검증한다. UA 판별 오류가 나더라도 두 보기 모두 선택 가능하다.
2. 모든 기기의 악보 설정에 `한 줄 / 여러 줄` 선택을 제공한다. 사용자의 명시적 선택을 `tempori:view-mode`에 `horizontal` 또는 `wrapped`로 저장한다. 우선순위는 유효한 저장 선택 → 최초 기기 기본값이다. 같은 브라우저의 다른 악보와 재방문에도 적용하고 서버/다른 기기 동기화는 하지 않는다. 저장 실패 시 현재 세션 선택은 유지하고 재방문까지 기억되지 않을 수 있음을 알린다. 회전·창 크기 변경·태블릿 분할 화면·입력 장치 변경은 선택을 바꾸지 않는다. 여러 줄 설정의 줄당 마디 수는 보존하되 한 줄 모드에서는 숨긴다.
3. 한 줄 보기 최초 진입 시 입력 방식에 맞는 짧은 안내를 제공한다. 터치에서는 가로 스와이프, 데스크톱에서는 가로 스크롤바·트랙패드·Shift+휠·포커스된 악보의 좌우 키를 지원한다. 일반 세로 휠과 입력창의 키 입력을 전역으로 가로 이동에 가로채지 않는다. 악보를 화면 전체 폭에 억지로 축소하지 않고 가로 회전이나 넓어진 창에서는 더 많은 마디가 보이게 한다.
4. 재생 중 현재 마디 시작을 보이는 가로 영역 약 1/3 위치에 유지한다. 처음/끝은 범위를 제한하고 반복·되돌이표 이동은 실제 재생 순서의 마디를 따른다. 좌우 이동 중 세로 문서 위치를 임의로 바꾸지 않는다.
5. 사용자가 드래그·휠·키보드로 이동하면 따라가기를 중지한다. 시간 경과만으로 다시 빼앗지 않고 `현재 마디로` 버튼 또는 새 재생 시작으로 복귀한다. 프로그램 이동은 수동 입력으로 오인하지 않는다.
6. 펜/형광펜/지우개 모드의 한 손가락 입력은 필기, 스크롤 모드의 입력은 이동이다. 필기 중 따라가기는 멈추고 펜 스트로크가 끊기지 않게 한다. 브라우저 확대를 전역 차단하지 않는다.
7. 하단 보관함/재생/주석 조작부는 유지한다. 가로 화면에서 보표 높이가 부족하면 억지 축소 대신 세로 이동도 허용하고 숨겨진 조작부 없이 기존 여러 줄 보기로 전환 가능하게 한다.
8. 기존 주석은 여러 줄 보기에서 그대로 유지한다. 한 줄 주석은 별도 보기 식별자로 저장하며 기존 키/문서를 덮어쓰거나 자동 변환하지 않는다. 전환 시 주석이 보기별로 관리됨을 안내한다. 두 보기 주석 공유/자동 변환은 이번 범위 밖이다.

## 단계별 구현과 수용 기준

### 1. 렌더링·성능 검증을 먼저 수행

- 대상: `OsmdViewer.tsx`, `temporiLayout.ts`, `musicXml.ts`; 새 `utils/viewMode.ts` 및 테스트.
- 실제 OSMD로 한 줄 옵션을 load 전에 적용하고 XML 줄바꿈/고정 마디 수/여러 줄 줌 보정을 분리한다. 각 모드의 유효 레이아웃 검증도 분리한다.
- 8·100·300마디, 피아노 양손·반복·음자리표 변경을 포함한 비민감 테스트 악보로 첫/중간/마지막 마디가 모두 렌더되는지 확인한다.
- 사전 성능 합격 기준: 비민감 300마디 피아노 fixture를 명시한 휴대폰·태블릿·데스크톱 대표 시험 환경에서 각각 5회 측정하여 최초 렌더 8초 이내, 모드 전환 5초 이내, 10초 연속 스크롤의 프레임 간격 p95 50ms 이내를 목표로 한다. 마디 누락·빈 canvas·탭 종료는 0건이어야 한다. 시험 기종/OS/브라우저/DPR, 최대 SVG 폭과 canvas backing 크기를 기록한다. 기준 미달이면 해당 환경의 한 줄 보기 출시를 보류하고 분할 렌더 설계를 리뷰한다. 수치는 달성 보장이 아닌 사전 합격 목표이며 기기 검증 불가 시 미검증으로 남긴다.
- 300마디에서 누락·탭 종료·지속적인 조작 멈춤이 발생하면 한 줄 보기 배포를 보류한다. 분할 SVG 렌더링을 별도 설계 검토하고, 조용히 마디를 잘라내지 않는다. 실행 중 렌더 실패는 이유와 여러 줄 보기 복귀를 제공한다. 실패 복귀만으로 사용자의 저장된 선호를 덮어쓰지 않는다.

### 2. 보기 상태·가로 좌표·따라가기

- 대상: `Tempori.tsx`, `OsmdViewer.tsx`, `TemporiAutoScroller.tsx`, `measureTiming.ts`, `scrollAnchor.ts`, `scoreViewport.ts`, `FloatingSettingsPanel.tsx`, `index.css`.
- `viewMode: 'wrapped' | 'horizontal'`을 부모가 소유하고 렌더 revision에 포함한다. 전환 중 재생/카운트인을 정지하고 현재 물리 마디·반복 구간·조옮김·설정을 유지한다. 이전 비동기 렌더 결과는 폐기한다.
- 기기 분류와 무관하게 동일한 보기 선택 UI와 렌더 분기를 사용한다. 기기 판별 함수는 저장 선택이 없는 최초 초기화에만 관여한다. 회전·창 크기 변화 시 모드는 그대로 두고 현재 마디를 새 viewport에 맞게 복원한다.
- 스크롤 viewport와 이동하는 악보 content를 별도 요소로 둔다. DOM rect에서 content좌표를 얻는 변환을 명시하고 highlight·클릭·주석에서 같은 기준을 사용한다. 사용자 스크롤은 재렌더를 유발하지 않는다.
- X축 따라가기와 수동 탐색 상태를 분리한다. 수동 탐색/펜 입력에서 자동 이동 정지, 복귀 버튼, 반복 구간 뒤로 이동, 회전 후 같은 마디 유지, reduced-motion을 검증한다.
- 세로 모드 기존 line/page 자동스크롤 및 래퍼 회귀 테스트는 그대로 통과해야 한다.

### 3. 주석·선택 호환성 및 메모리 제한

- 대상: `TemporiAnnotationLayer.tsx`, `TemporiMeasureClickOverlay.tsx`, `temporiAnnotations.ts`, `types/temporiAnnotation.ts`, `temporiStorage.ts`, 관련 테스트.
- 한 줄 모드 canvas backing store는 보이는 영역과 제한된 여유 폭만 사용한다. 전체 수만 픽셀 길이의 canvas를 만들지 않는다. 렌더 crop과 pointer 역변환에 scrollLeft를 반영하고 기존 여러 줄 저장 데이터는 수정하지 않는다.
- 캔버스 초기 상한은 장당 4메가픽셀/한 변 4096px, 유효 DPR 최대 2로 정한다. viewport와 최대 좌우 25% 여유 영역만 그리며 상한을 넘으면 유효 DPR을 낮춘다. 두 backing canvas 합계 8메가픽셀 이하를 assertion으로 검증한다. 실제 지원 기기에서 선명도·메모리를 함께 검증하고 상한 변경은 이유를 기록한다.
- 한 줄 주석은 처음부터 별도 v2 문서로 저장한다: `tempori:annotations:horizontal:<id>`, `{version:2, strokes:[{id,tool,color,widthStaffRatio,segments:[{measureIndex,points:[{x,y}]}]}]}`. 물리 마디 인덱스와 그 마디의 보표 사각형에 대한 상대 좌표를 저장하고, 렌더 revision마다 현재 마디 사각형으로 재투영한다. 너비는 보표 높이 비율로 저장한다. 여러 마디를 가로지르는 획은 경계에서 segment로 나누되 하나의 stroke ID를 유지해 실행취소/지우개 단위를 보존한다. 보표 밖 필기를 잘라내지 않도록 y 비율은 0~1 밖도 허용한다. 이는 마디 위치 고정이며 개별 음표 자동 추적은 아니다. 조옮김·회전·줌·반복 구간에서도 마디 연결을 검증한다. 기존 v1 문서는 읽기/쓰기 방식 그대로 보존한다.
- 보기별 주석 읽기/저장/실행취소/지우기/전체지우기를 격리한다. 기존 기록이 있는 악보·주석 없는 악보·저장 실패·전환 반복을 검증한다.
- 화면의 전체 지우기는 현재 보기만 대상으로 한다. 보기 전환 시 유효한 진행 중 획을 기존 보기 문서에 확정·저장한 뒤 전환하며 저장 실패는 기존 보기에서 재시도를 제공한다. 회전/pointercancel도 유효 점을 확정하고 빈 획만 폐기한다. 지연 저장은 생성 시점의 악보 ID/보기/문서 revision을 캡처하여 빠른 전환 뒤 다른 문서에 기록하거나 지운 획을 되살리지 못하게 검증한다.
- `TemporiLibraryPage.tsx`/`temporiRepository.ts`의 악보 삭제 성공 후 해당 ID의 기존 여러 줄 및 새 한 줄 주석 키를 모두 정리한다. 삭제 실패 시 어느 주석도 지우지 않는다. 주석 정리 실패는 재시도 가능하게 보고하고 다른 악보 키를 삭제하지 않는다. 로컬 라이브러리 전체 삭제 경로도 동일 정책을 적용한다.
- 화면 밖 마디 클릭 요소/주석 처리량을 제한하고 마지막 마디까지 접근 가능해야 한다. 음표/표준 MusicXML 내용과 악보 ID는 변경하지 않는다.

### 4. 독립 리뷰와 실제 검증

- Node: 기기 기본값, 저장 선택 우선순위(휴대폰의 wrapped·PC의 horizontal 포함), 잘못된 저장값·저장 실패, 보기 상태 전환, X 좌표/경계값/반복, 수동 탐색 복귀, 주석 모드 분리, 기존 테스트 전체.
- React: 모든 기기에 두 선택 노출, 선택 후 재방문/다른 악보에서 유지, 회전·resize에 의한 선택 유지, 로딩/실패 복귀, render revision, toolbar 접근성, 직접 스크롤과 펜 충돌, 모드 변경 후 위치 복원.
- 타입 검사·lint·빌드: 현재 허용된 의존성 사용 가능. Vite/Vitest/개발 서버의 실제 `.env*` 자동 로딩은 비활성화한 검증 설정으로 실행한다. 비밀 환경변수나 파일을 읽어 실행하지 않는다.
- 브라우저: 휴대폰·태블릿·데스크톱 크기의 Chromium/WebKit에서 두 보기, 300마디, 주석, 반복, 확대, 마지막 마디, 고정 dock 겹침을 검증한다. 저장 선택 없는 iPad 데스크톱 UA·PC는 여러 줄로 시작하되 한 줄 선택 후 재방문에도 유지해야 한다. 휴대폰 회전·iPad 분할 화면·PC 창 크기 변경에도 모드와 현재 마디를 유지한다. 마우스 스크롤바·트랙패드·Shift+휠·키보드·터치/펜 및 입력창과의 충돌을 확인한다.
- 실제 iPhone/Android/iPad 및 데스크톱 브라우저 확인은 에뮬레이션과 별도 결과로 보고한다. 기기 접근이 없으면 미검증으로 남기며 성공 주장하지 않는다. 비밀 설정이 필요한 서비스 실행은 사용자가 설정·실행한다.

## 범위·위험

- CSS 변경만으로 완료할 수 없는 렌더/좌표/상태 기능이다. 먼저 실제 OSMD 한 줄 성능을 입증한 뒤 UI·주석을 연결한다.
- 긴 단일 SVG 한계와 필기 좌표 안정성이 주요 위험이다. 휴대폰·태블릿 UA 오분류는 최초 기본값에만 영향을 주며 기능 접근을 제한하지 않는다. 수동 전환과 기존 모드 복귀를 항상 유지한다.
- 이번 턴은 계획만 작성한다. 실제 구현·배포·환경변수 수정 없음.

## 검토 기록

- 코드와 설치된 OSMD 타입 선언을 확인했다. 제품 코드 및 기존 저장 데이터는 변경하지 않았다.
- 자체 검토: 기능 요구, 기존 주석 보호, 이전 모드 회귀, 성능 우선 검증, 비밀 파일 로딩 방지 포함.
- 독립 계획 리뷰(`gpt-6-astra`, `high`)에서 지적한 주석 좌표/버전, 삭제 수명주기, 성능 기준을 반영했다. 한 줄 v2 마디 기준 저장·보기별 지연 저장 격리·획 확정 정책·canvas 픽셀 상한·사전 성능 목표를 명시했다. 제안 계획이며 성능이나 실기기 동작을 입증한 결과는 아니다.
- 사용자 추가 요청 반영: 휴대폰 전용 기능 제한을 제거하고 모든 기기 보기 선택으로 확대했다. 제목/파일명, 저장 선택 우선순위, 데스크톱 입력, 기기별 검증 및 성능 수용 기준을 함께 수정했다. 이번 문서 수정은 자체 검토했으며 앞선 독립 리뷰가 확대 범위를 검증했다고 주장하지 않는다. 제품 코드는 변경하지 않았다.
