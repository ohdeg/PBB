# 로그인 후 뒤로가기 수정 계획

로그인에 성공하면 현재 방문 기록의 `/login` 항목을 복귀 목적지로 교체한다. 유효한 세션으로 기존 로그인 주소에 다시 진입해도 로그인 폼을 표시하지 않는다.

## 1. 실패 동작을 테스트로 고정

- [ ] `frontend/src/pages/LoginPage.test.tsx`에서 메모리 라우터와 모의 로그인 응답을 사용한다. 구분 가능한 공개 페이지에서 로그인으로 이동한 뒤 성공시키고 뒤로가기를 한 번 실행한다. 도착지가 처음의 공개 페이지인지 검사한다. 홈에서 시작해 홈으로 돌아가는 경우만 검사하면 기록 한 칸이 더 생긴 결함을 놓칠 수 있다.
- [ ] 유효한 토큰으로 이전 방문 기록의 로그인 주소에 진입하는 경우와 로그인 주소에서 시작하는 경우를 각각 검사한다. 폼이 마운트되지 않고 목적지로 이동해야 한다. 토큰이 없으면 폼이 보이고 로그인 실패 시 같은 주소에서 재시도할 수 있어야 한다.

## 2. 로그인 화면이 이동을 한 번만 처리

- [ ] `frontend/src/pages/LoginPage.tsx`에서 기존 인증 저장소의 `accessToken`을 구독한다. 모든 훅을 호출한 뒤 토큰이 있으면 폼 대신 `<Navigate to={destination} replace />`를 반환한다. 성공 핸들러는 토큰 저장과 성공 알림을 처리하고 기존 `navigate(...)` 호출을 제거한다.
- [ ] 기존 `resolvePostLoginPath(from: unknown): string`에서 같은 출처의 루트 기준 경로를 검증한다. 유효하면 쿼리와 해시까지 보존한다. 값 누락, 외부 주소, 역슬래시 등으로 출처가 바뀌는 주소, 정규화 후 로그인 라우트와 일치하는 주소는 홈으로 보낸다. 복귀 안내 문구도 같은 검증 결과를 사용한다.
- [ ] 목적지 처리 테스트에 정상 내부 경로, 외부 주소, `//example.test`, `/LOGIN/?next=x#top`을 포함한다. 로그인 페이지와 목적지 페이지의 기존 접근 권한 검사는 각각 해당 라우트가 담당한다.

## 3. 브라우저에서 완료 조건 확인

- [ ] `frontend/e2e/auth.spec.ts`에 모의 로그인·세션 복원 응답을 사용한 시나리오를 추가한다. 성공 후 뒤로가기 한 번으로 원래 공개 페이지에 도착하고, 앞으로가기를 누르면 로그인 후 목적지에 도착해야 한다.
- [ ] 보호 경로에서 전달한 `state.from`으로 정확히 복귀하는지 확인한다. 새로고침으로 `/login`에 직접 진입할 때는 기존 `App.tsx`의 세션 복원 완료 시점을 이용한다. 복원 성공 시 홈, 세션 만료 시 로그인 폼, 로그아웃 후 재진입 시 로그인 폼을 확인한다.
- [ ] 프런트엔드에서 대상 Vitest, Playwright 인증 시나리오, TypeScript 검사와 변경 파일 린트를 실행한다. 실제 환경 파일을 읽지 않는 테스트 설정을 사용하고, 브라우저 실행이 불가능하면 미검증 항목을 기록한다.
