# Dieta UI/UX 리디자인 계획

## 디자인 방향

밝은 식사 일지를 기준으로 설계한다. 식탁에서 휴대폰을 한 손에 들고 방금 먹은 음식을 적는 상황이 첫 화면의 기준이다. 현재 식사 탭에서는 같은 음식이 영양 상세와 입력 목록에 반복되고, 간편 기록의 여러 버튼이 입력창보다 먼저 보인다. 한 끼에 대한 기록·조회·수정을 같은 자리에 모은다.

- 기본 화면은 따뜻한 백색(#FAF9F5), 본문은 짙은 먹색(#272A25), 주요 동작은 잎색(#306547)을 사용한다. 옅은 녹색(#E7F0DB)은 선택일과 선택한 끼니에 한정한다. 다크 모드는 사용자의 테마 선택을 따르고, 같은 위계를 따뜻한 짙은 회색과 명도 차로 표현한다. PBB 공통 헤더는 유지한다.
- 제목은 24~28px, 음식명과 입력은 16px, 단위와 보조 정보는 13~14px에서 시작한다. 한글은 기존 본문 서체를 쓰고 kcal 숫자에는 고정폭 숫자 스타일을 적용한다. 숫자와 단위의 크기를 달리한다.
- 끼니 사이에는 가는 선과 여백을 쓴다. 배경을 채운 면은 입력 중인 영역과 달력·선택창에 집중한다. 습관 점수, 응원 문구, 장식 이미지처럼 식사 기록에 기여하지 않는 요소는 추가하지 않는다.

## 1. 식사 화면을 먼저 설계한다

- 상단 한 줄에 ‘식사’와 ‘저장한 음식’을 놓고 아래에 날짜 탐색을 배치한다. 가운데 날짜를 누르면 달력을 연다. 과거 날짜를 보고 있을 때는 ‘오늘로’를 가까이 둔다.
- 날짜 아래 하루 요약은 한 덩어리로 둔다. kcal를 먼저 읽고 그 아래 탄수화물·단백질·지방을 g 단위로 읽게 한다. 아무것도 입력하지 않은 날에는 바로 오늘의 첫 식사를 적을 수 있게 한다. 아직 분석하지 않은 날과 실제 0 kcal는 구분한다.
- 아침·점심·저녁·간식을 세로로 배열한다. 접힌 줄에는 끼니, 대표 음식명, 소계를 놓는다. 펼치면 음식·분량·영양값과 해당 날짜에 허용되는 편집 동작을 제공한다. 미분석 항목도 같은 목록에 둔다. 분석 결과로 한 입력이 여러 음식으로 나뉜 경우 원래 입력을 기준으로 수정·삭제 가능 여부를 결정한다.
- 각 끼니의 ‘+’를 누르면 그 자리에 입력칸이 열리고 끼니가 미리 선택된다. 바로 아래 ‘불러오기’에서 전날 식사·자주 먹는 식사·평균 추정을 선택한다. ‘자주 먹는 식사로 저장’은 현재 끼니에 항목이 있을 때 끼니 메뉴에 표시한다. 레시피 보관함과 자주 먹는 조합은 이름과 동작을 구분한다.
- 분석 가능한 날은 목록 끝에 기본 또는 추가 분석 버튼 하나와 해당 상태를 표시한다. 과거 날짜는 조회에 집중한다. 완료 토스트는 12px 아래에서 220ms ease-out으로 올라오며, 결과와 오류는 날짜 화면에서 다시 확인할 수 있다.

### 처음 열리는 끼니

오늘은 사용자 시간대 기준 05시부터 아침, 11시부터 점심, 17시부터 저녁, 22시부터 다음 날 05시 전까지 간식을 기준으로 삼는다. 해당 끼니에 기록이 있으면 이후 비어 있는 끼니를 먼저 열고 모두 채워졌으면 간식을 연다. 어제는 아침부터 비어 있는 끼니를 찾는다. 분석 전 직접 입력, 저장 음식과 평균 추정도 기록으로 센다. 날짜를 처음 열 때 한 번만 선택하고, 폴링이나 음식 저장 후에는 사용자가 고른 끼니와 끼니별 입력 초안을 유지한다.

## 2. 나머지 탭에 같은 기준을 적용한다

| 화면 | 우선해서 보일 내용 | 세부 동작 |
| --- | --- | --- |
| 홈 | 오늘 입력한 식사·활동과 다음에 기록할 항목 | 날짜와 실제 음식명을 보여주고 해당 기록으로 이동한다. 체중 추이와 주간 체크인은 그 아래에 둔다. |
| 활동 | 걸음 수와 운동 시간·운동 소모량 | 걸음으로 계산한 열량은 읽기 전용 결과로, 운동 소모량은 단위가 붙은 입력란으로 구분한다. 전날 운동·평균 가져오기는 입력 옆에 둔다. |
| 설정 | 현재 목표, 식사 분석 예약 시간 | 현재 값을 먼저 보여주고 편집을 선택한 그룹만 펼친다. AI 동의 설명과 삭제 확인을 유지한다. |

## 3. 구현 순서와 완료 기준

1. 390px 기준 식사 탭의 빈 날·분석 전·분석 후·과거 조회 네 상태를 먼저 시안으로 만든다. 대표 시안 한 장에서 날짜, 음식 추가 위치, 끼니 소계를 바로 찾을 수 있어야 한다.
2. dieta.css의 중복된 카드·제목·여백 규칙을 공통 색상과 간격으로 정리한다. DietaMealsPage, DietaMealDetails, DietaQuickMeals, DietaMealDate 순서로 결합한다. 기존 조회 응답과 큐 ID로 누락 없이 표시할 수 있는지 먼저 확인한다.
3. 홈·활동·설정과 하단 내비게이션으로 확대한다. 작은 화면에서는 키보드가 열린 상태의 저장 버튼과 토스트 위치를 확인한다.
4. 320px·390px·820px·데스크톱에서 한글 긴 음식명, 큰 글자, 빈 데이터, 긴 목록을 테스트한다. 라이트·다크 테마, 키보드 포커스, 달력 복귀, 동작 줄이기를 확인한다. 기존 식사 추가·불러오기·저장·분석 횟수·과거 조회 테스트를 재실행한다.
