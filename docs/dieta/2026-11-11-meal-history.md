# Dieta 날짜별 식사 기록과 영양 상세 구현 계획

식사 탭에서 날짜 하나를 선택해 그날의 식단, 분석 상태, 총섭취량과 음식별 영양을 확인한다. React 식사 화면과 Spring의 일별 조회·분석 저장 경로가 대상이다. 관련 기준은 [간편 기록](2026-11-09-quick-entry.md)과 [예약 분석](2026-11-08-scheduled-meal-analysis.md)에 있다.

## 1. 날짜별 조회

- [x] DietaController와 DietaService에 인증된 사용자 전용 GET /api/v1/dieta/meal-days/{day}를 추가한다. 날짜, 분석 단계와 상태, 리뷰, 일 합계, 끼니별 합계와 음식 목록, 각 값의 출처와 분석 반영 여부를 반환한다. 식단만 남은 날과 합계만 남은 날도 정상 응답으로 구분한다.
- [x] 기존 섭취 로그와 분석 당시 식단 스냅샷, 레시피, 평균 입력을 조합한다. 최근 입력은 최신 미분석 항목도 포함한다. Redis 큐가 만료된 날짜는 영구 저장된 자료를 이용한다. 저장되지 않고 만료된 입력은 복원할 수 없으므로 누락된 값을 0으로 표시하지 않는다.
- [x] 사용자 시간대와 날짜별 권한을 적용한다. 오늘·어제는 기존 조건에서 입력과 분석이 가능하고, 그 이전은 조회 전용으로 가정한다. 조회와 달력 이동은 분석 시작, 횟수 차감, 큐 상태 변경을 유발하지 않는다.

## 2. 음식별 영양 저장

- [x] DietaGeminiRequestBuilder, 응답 DTO, DietaMealBreakdown을 확장한다. 기존 분석 요청에 입력 항목의 식별자를 포함하고 결과에 음식명, 분량, kcal, 탄수화물·단백질·지방(g)을 받는다. 한 입력에 여러 음식이 있으면 해당 입력 아래 여러 음식 행을 허용한다. 분량을 추정한 경우 표시한다.
- [x] 미등록·중복 식별자, 누락 항목, 음수, 음식/끼니 합계 불일치를 검증한다. 표시는 반올림하고 비교에는 반올림 오차를 허용한다. 검증에 실패한 범위는 상세 미제공으로 처리하고 검증된 상위 합계를 보존한다. 저장 음식은 섭취 분량으로 환산하고 평균 입력은 끼니 단위로 표시한다. 같은 레시피 또는 반영 항목을 두 번 더하지 않는다.
- [x] 기존 dieta_day_records에 버전을 명시한 별도 JSON 기록으로 음식 상세를 저장한다. 기존 ANALYSIS를 읽는 평균 입력 기능과 호환한다. 기본·추가 분석 성공 시 기존 트랜잭션 안에서 해당 분석 결과 전체를 교체한다. 추가 분석 실패 시 마지막 성공 결과와 아직 반영되지 않은 입력을 구분한다. 과거 기록은 확보된 수준까지 제공한다.

## 3. 날짜 탐색과 식사 화면

- [x] DietaMealsPage와 dietaApi를 일별 조회에 연결한다. 전체 섭취 목록 요청과 ‘최근 식사 기록’ 카드를 제거한다. 식사 탭에 이전 날짜 버튼, 가운데 날짜 버튼, 다음 날짜 버튼을 만든다. 날짜 버튼으로 달력을 열고 오늘과 선택일을 구분하며 미래 날짜는 막는다. 달력에는 오늘로 돌아가는 동작을 둔다. 활동 탭과 공유하는 기존 날짜 컴포넌트의 동작을 보존한다.
- [x] 선택일의 하루 kcal·탄단지, 분석 상태·리뷰, 아침·점심·저녁·간식 목록을 표시한다. 끼니를 펼치면 음식명·분량·영양값 또는 미분석/상세 기록 없음 상태를 표시한다. 합계만 있는 날, 분석 전 입력만 있는 날, 기록이 없는 날을 구분한다.
- [x] 빠른 날짜 전환 시 이전 조회 응답과 입력 폼이 새 날짜에 섞이지 않도록 한다. 서버와 같은 시간대에서 오늘·어제를 판단한다. 날짜 이동과 기존 어제 자동 마감 트리거를 분리하고, 과거 날짜에서는 쓰기 버튼과 편집 전용 API 호출을 막는다.

## 4. 분석 완료 알림

- [x] 기존 toastStore와 ToastHost를 재사용한다. 수동 분석 성공 또는 화면을 연 동안 확인한 자동 분석 완료를 날짜·분석 단계·성공 회차 기준으로 한 번 알린다. 폴링과 수동 응답 중복, 탭 재진입, 기존 결과 열람은 알림을 반복하지 않는다. 다른 날짜를 보는 중에 시작한 작업이 완료되면 토스트에 실제 분석일을 표시한다.
- [x] 분석 완료 토스트는 최종 위치보다 약 12px 아래에서 시작해 약 220ms 동안 CSS `ease-out`으로 올라온다. 처음에 가장 빠르고 도착할수록 감속해 제자리에서 멈춘다. 기기의 동작 줄이기 설정에서는 이동 없이 표시한다.
- [x] 성공 토스트는 약 3.2초 후 사라지고 당일 결과는 카드에 남는다. 실패와 재시도 가능 여부는 해당 날짜 화면에 남긴다.

## 5. 인수 검증

- [ ] 백엔드에서 타 사용자 격리, 빈 날, Redis 만료, 과거 합계만 있는 데이터, 섭취 분량, 혼합 입력, 추가 분석 성공·실패 후 합계와 음식 중복 여부를 검증한다.
- [ ] 프런트에서 월말·연말·윤일 전환, 미래 차단, 자정 경계, 날짜 빠른 전환, 기존 편집 범위, 직접 날짜 선택, 상세 펼침과 토스트 중복 방지를 테스트한다.
- [ ] 모바일 크기 브라우저에서 달력 선택·닫기, 이전/다음 버튼 터치, 하단 내비게이션과 토스트 겹침을 확인한다. 키보드로 날짜 선택 및 닫기 후 포커스 복귀를 확인한다. 백엔드 호환 응답을 먼저 배포한 뒤 Pages를 배포한다.

## 로컬 검증 결과

Dieta 백엔드 단위 테스트 40개와 프런트엔드 테스트 57개가 통과했다. TypeScript 검사, 변경한 프런트 파일의 린트, 환경 파일을 사용하지 않는 프런트 빌드를 확인했다. 빌드한 화면을 테스트 API 응답으로 열어 390px과 820px 너비에서 윤일 선택, 포커스 복귀, 음식 상세와 토스트 표시 및 해제를 확인했다. 일반 설정에서 등장 시간은 220ms이고, 동작 줄이기 설정에서 등장 애니메이션은 꺼진다. Docker 데몬이 없어 MySQL·Redis 통합 테스트 실행과 운영 연동 검증은 남아 있다.
