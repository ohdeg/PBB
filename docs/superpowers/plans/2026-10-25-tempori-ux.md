# Tempori UI/UX 개선 계획서

> 실행 지침: `executing-plans`를 적용해 한 구현 담당자가 순서대로 수행한다. 누락된 companion helper는 실행하지 않는다. 각 단계의 행동 테스트와 최종 코드 리뷰를 진행하며, 자동 커밋이나 배포는 하지 않는다.

**상태:** 5단계 제품 코드 및 회귀 테스트 작성, 독립 코드 리뷰 수정 완료. 허용된 Node 검증 통과. React/타입/빌드/브라우저·실기기 검증은 접근 정책으로 미실행.

**목표:** 아이폰에서 악보를 연 뒤 설정·구간 선택·재생·오류 복구를 예측 가능한 흐름으로 제공한다.

**구조:** 기존 React 컴포넌트와 디자인 시스템을 유지한다. 적용된 연습 설정과 편집 중 설정을 구분하고, OSMD의 준비 상태를 부모 뷰어에 전달해 재생 가능 시점을 제어한다.

**기술:** React 19, TypeScript, Zustand, OpenSheetMusicDisplay, 기존 Vitest/Testing Library 및 브라우저 검증 도구.

**요구사항 근거:** 이 대화의 UI/UX 검토 6개 항목과 사용자 요청. 아래 동작 정의가 구현의 수용 기준이다.

## 1. 범위와 제약

- 기존 색상·타이포그래피·악보 표시 스타일과 데스크톱 기능을 유지한다.
- 앞서 수정한 iOS 파일 선택 필터 생략과 선택 후 확장자·내용 검증을 보존한다.
- 악보 저장 형식, IndexedDB 스키마, 서버 API, 인증, 환경변수를 변경하지 않는다.
- 새 패키지나 전면적인 상태 관리 개편은 추가하지 않는다.
- `PlaybackControls`의 독립 메트로놈 모드도 사용처를 조사해 기존 즉시 조작 동작을 보존한다.
- 실제 `.env`, ignored 경로 및 그 안의 실행 도구를 읽거나 실행하지 않는다. 접근 제한을 우회하기 위한 복사·재설치도 하지 않는다.
- 테스트가 실행 불가능하면 코드 검토와 실행 검증을 구분해 보고한다. iPhone Safari 실기기 검증은 데스크톱 에뮬레이션으로 대체했다고 주장하지 않는다.

## 2. 변경 후 사용자 흐름

### 악보 열기

1. 악보를 준비하는 동안 상태 안내와 비활성 재생 버튼을 표시한다.
2. 준비가 끝나면 재생 버튼을 활성화한다.
3. 아티스트가 없으면 부제 줄을 생략한다. 로딩 문구는 로딩 중에만 표시한다.
4. 실패하면 오류 메시지와 ‘다시 시도’, ‘보관함으로’를 표시한다.

### 설정 변경

- 기본 영역: BPM, 조옮김, 줄당 마디 수, 시작·끝 마디, 반복, 자동 스크롤, 메트로놈 소리, 마디 강조.
- ‘고급 설정’ 접기 영역: 박자·프리셋, 구간별 템포, 박별 강약·세분화.
- 스크롤되는 본문 밖 하단 영역에 ‘취소’, ‘적용’, ‘적용하고 재생’을 고정한다. 좁은 화면에서는 버튼을 줄바꿈하되 모두 접근 가능하게 한다.
- ‘적용’: 편집값을 반영하고 패널을 닫는다. 재생은 시작하지 않는다.
- ‘적용하고 재생’: 편집값을 반영하고 패널을 닫은 뒤, 갱신된 악보·타이밍이 준비되면 새 구간 시작점에서 예비박을 시작한다.
- 설정 패널의 기존 상단 ‘재생’ 버튼은 악보 모드에서 제거한다. 패널이 열린 동안 하단 플로팅 재생은 숨겨 우회 동작을 없앤다.
- X, Escape, ‘취소’는 변경값을 버리고 닫는다. 변경 중에는 ‘취소하면 변경 내용이 사라집니다’ 안내를 표시한다.
- 기존 BPM 저장 기능은 ‘다음 악보의 기본값으로 저장’으로 명확히 표시한다. 저장 대상이 BPM과 줄당 마디 수뿐이며 현재 연습에 적용하려면 적용 버튼을 눌러야 함을 명시한다.

### 마디 이동과 구간 선택

- 기본 탭은 재생 위치 이동만 수행하며 연습 범위를 바꾸지 않는다.
- 선택된 연습 범위 밖으로 이동해도 범위는 유지한다. 재생은 범위 밖 위치에서 시작하지 않고 범위 시작점으로 돌아간다.
- 악보 위에 ‘구간 선택’ 버튼을 둔다. 선택 모드에서만 첫 탭으로 시작점, 두 번째 탭으로 끝점을 지정한다.
- 안내는 ‘시작 마디를 선택하세요’ → ‘끝 마디를 선택하세요’로 바뀐다. 선택 취소 버튼을 제공한다.
- 두 번째 탭 후 두 마디를 오름차순으로 정렬해 범위를 적용하고 선택 모드를 종료한다. 같은 마디를 두 번 탭하면 한 마디 구간이 된다.
- 선택 취소는 기존 범위를 보존한다. 선택 도중 재생은 비활성화하고, 필기 도구 활성화·악보 교체·설정 열기는 선택 모드를 취소한다.

## 3. 구현 순서 및 완료 기준

### 단계 1 — 로딩·렌더링 상태와 복구 통일

**수정:**
- `frontend/src/pages/TemporiPage.tsx`
- `frontend/src/features/tempori/Tempori.tsx`
- `frontend/src/features/tempori/components/OsmdViewer.tsx`
- `frontend/src/features/tempori/components/FloatingPlaybackButton.tsx`

**인터페이스:** `TemporiRenderStatus = 'loading' | 'ready' | 'error'`. `OsmdViewer`에 `onRenderStatusChange(status: TemporiRenderStatus): void`, `renderRevision: number`를 추가한다. 플로팅 재생 버튼에는 `disabled?: boolean`을 추가한다.

- [ ] 로딩 중/실패 상태의 재생 차단, 준비 완료 후 활성화, 아티스트 없는 정상 악보의 부제 생략을 검증하는 실패 테스트를 먼저 작성한다.
- [ ] OSMD의 로드·렌더·레이아웃 및 스냅샷 생성 완료 후에만 ready를 통지한다. 이전 실행의 비동기 완료가 새 악보 상태를 덮어쓰지 않도록 취소 처리를 확인한다.
- [ ] 로딩·오류에서는 재생·예비박·예약된 재생을 중단하고 이전 스냅샷으로 재생하지 않게 한다.
- [ ] 상위 메타데이터 오류는 상세 재조회, 파일 오류는 파일 재조회, OSMD 오류는 revision 증가로 재렌더링한다. 실패 단계에 맞는 재시도만 수행한다.
- [ ] `TemporiPage.test.tsx`, `Tempori.test.tsx`, `components/OsmdViewer.test.tsx`에 성공/실패/재시도/오래된 응답 시나리오를 검증한다.

**완료 기준:** 빈 화면에서 활성 재생 버튼을 눌러도 반응 없는 상태가 사라지고, 재시도 후 정상적으로 다시 연습할 수 있다.

### 단계 2 — 설정 적용과 재생 연결

**수정:** `Tempori.tsx`, `components/PlaybackControls.tsx`, `types/temporiPractice.ts`, 필요 시 `hooks/useTemporiPlaybackDerived.ts`.

**인터페이스:** `PlaybackControls`에 `onApplyAndPlay?: () => void`, `onCancelSettings?: () => void`를 추가한다. 내부 `applyPracticeSettings(draft: PracticeSettingsDraft, intent: 'apply' | 'play'): void`가 공통 적용 경로를 담당한다.

- [ ] BPM 120→80 변경 후 ‘적용하고 재생’이 80 BPM으로 시작하는 테스트를 먼저 작성한다. React 상태 반영 전 기존 값으로 예비박이 시작되지 않아야 한다.
- [ ] 적용 요청에 revision을 부여한다. 렌더링이 필요한 변경은 해당 revision의 ready 이후, 타이밍만 바뀐 경우에는 새 파생 타이밍 반영 이후 재생한다. 임의 timeout으로 동기화하지 않는다.
- [ ] Safari 오디오 활성화는 ‘적용하고 재생’의 사용자 클릭 핸들러에서 요청한다. 실제 예비박 시작은 준비 완료 후로 분리한다.
- [ ] 연속 클릭·재시도·악보 이동·언마운트·오류에서 예약 재생이 중복되거나 뒤늦게 시작하지 않게 한다.
- [ ] ‘적용’은 무음·정지 상태를 유지한다. 취소는 적용된 설정과 저장값을 바꾸지 않는다.
- [ ] `Tempori.test.tsx`에서 조옮김+줄당 마디 수 변경 후 대기, 렌더 실패 시 시작 금지, 범위와 반복 반영, 재생 중단, 기본값 저장의 독립 동작을 검증한다.

**의존성:** 단계 1의 준비 상태 계약.

- [ ] 단계 2의 버튼을 고정 footer로 옮긴다. 메트로놈 모드의 재생·저장 UI는 보존한다.
- [ ] 패널 높이와 하단 안전 영역을 고려하고, 본문 스크롤이 페이지로 의도치 않게 이어지는지 점검한다.
- [ ] 패널 열기 시 첫 유효 컨트롤로 키보드 포커스를 이동하고 닫기 후 트리거로 복귀한다. 모바일에서는 숫자 입력으로 자동 포커스해 키보드를 열지 않는다.
- [ ] 닫기 및 주요 터치 버튼은 최소 44×44 CSS px의 조작 영역을 확보한다.
- [ ] 설정이 열린 동안 플로팅 재생을 숨기고, Space 단축키가 적용 전 재생을 실행하지 않게 한다.
- [ ] `components/PlaybackControls.test.tsx`, `components/FloatingSettingsPanel.test.tsx`에서 버튼 경로·취소·접힘 상태·포커스 복귀와 메트로놈 모드 회귀를 검증한다.

**완료 기준:** 긴 설정 본문을 어디까지 스크롤해도 취소·적용 버튼을 사용할 수 있다.

### 단계 4 — 마디 이동과 구간 선택 분리

**수정:** `Tempori.tsx`, `components/TemporiMeasureClickOverlay.tsx`, `hooks/useTemporiPlaybackDerived.ts`, `frontend/src/index.css`.

**상태:** `measureInteractionMode: 'seek' | 'range'`를 추가한다. 기존 `rangeSelectionStartMeasure`는 range 모드에만 사용한다.

- [ ] 일반 탭 시 start/end가 유지되는 테스트를 먼저 작성한다.
- [ ] 구간 선택 모드·현재 안내·취소 버튼을 제공하고 키보드 Enter/Space로도 두 마디를 선택할 수 있게 한다.
- [ ] 첫 탭은 임시 시작점만 보관한다. 두 번째 탭에서만 범위를 확정하고 시작점으로 이동한다.
- [ ] 역순 8→3은 3~8, 동일 마디 4→4는 4~4로 처리한다. 취소는 기존 범위와 반복 설정을 보존한다.
- [ ] 필기 모드와 동시 활성화를 막고, 모드 종료 시 임시 강조를 제거한다.
- [ ] `Tempori.test.tsx`와 기존 `hooks/useTemporiPlaybackDerived.test.tsx`에 범위 밖 이동 후 재생, 취소, 반복기호가 있는 악보의 물리 마디/재생 순서 구분을 검증한다.

**완료 기준:** 악보를 탐색하는 탭만으로 연습 구간이 변경되지 않는다.

**수정:** `components/TemporiUploadConfirm.tsx`, `components/PlaybackControls.tsx`, `pages/TemporiLibraryPage.tsx`, `pages/TemporiPage.tsx`, `Tempori.tsx`, `components/OsmdViewer.tsx`, `i18n/messages.ts`, `i18n/messagesPractice.ts`.

- [ ] BPM label과 input을 id/htmlFor로 연결하고, 반복 렌더 시 ID가 충돌하지 않게 한다.

- [ ] `components/TemporiUploadConfirm.test.tsx`에서 제목 입력 이름, 초기 포커스, 오류 알림을 검증한다. 관련 설정·뷰어 테스트에서 accessible name으로 컨트롤을 찾는다.
- [ ] 변경 diff를 별도 코드 리뷰하고, 유효한 지적 수정 후 해당 검증을 다시 수행한다. 주요 변경은 허용된 독립 리뷰어가 가능하면 활용한다.

## 4. 검증표

| 검증 | 시나리오 | 통과 조건 |
|---|---|---|
| 등록 | iPhone Safari에서 MXL 선택, 제목 확인, 저장 | 선택 가능, 키보드가 불필요하게 자동 표시되지 않음, 잘못된 확장자는 거절 |
| 설정 | BPM 120→80, 조옮김 +2, 줄당 4→2 후 적용하고 재생 | 갱신 완료 뒤 새 값으로 예비박·재생, 중복 시작 없음 |
| 취소 | 여러 설정 변경 후 취소/X/Escape | 기존 설정 유지, 다음 열기 시 적용된 값 표시 |
| 구간 | 이동 탭, 구간 선택, 역순/동일 마디, 선택 취소 | 이동은 범위를 유지하고 명시적 선택만 범위를 변경 |
| 오류 | 파일 조회 실패, OSMD 실패, 재시도 성공 | 재생 차단, 복구 버튼 동작, 오래된 비동기 완료 무시 |
| 모바일 | 390×844, 375×667, 가로 방향, 키보드 표시 | footer·닫기·주요 입력 접근 가능, 가로 넘침·고정 UI 겹침 없음 |
| 태블릿 | 768×1024 및 가로 방향 | 구간 선택과 필기 충돌 없음, 하단 버튼 겹침 없음 |
| 데스크톱 | 1440×900, Tab/Shift+Tab/Enter/Space/Escape | 포커스 식별·복귀 및 조작 가능, 편집 중 Space 오재생 없음 |
| 회귀 | 독립 메트로놈, 반복 재생, 자동 스크롤, 필기 | 기존 기능 유지 |

현재 접근 정책에서는 `frontend/node_modules`, 실제 환경파일과 일부 산출물 경로가 금지되어 있다. 다음 명령은 **사용자가 구성한 로컬 환경에서 실행할 검증 명령**이며, 이 계획 작성 중 실행한 결과가 아니다.

```sh
cd frontend
npm test -- src/features/tempori src/pages/TemporiPage.test.tsx
npm run lint
npm run build
```

컴포넌트 테스트는 기존 기본 환경이 node인 점을 고려해 필요한 파일에 jsdom 환경을 지정한다. 에이전트가 수행하는 검증은 허용된 경로·도구에 한정한다. 브라우저 확인은 허용된 실행 화면을 사용하며, 실기기 확인이 불가능하면 검증표에서 미확인으로 남긴다.

## 5. 계획 검토 결과 및 위험 관리

- 검토 6개 항목을 단계 1~5에 모두 배정했다. 기존 iOS MXL 수정은 회귀 검증에 포함했다.
- 가장 큰 위험은 상태 적용 직후 이전 타이밍으로 재생하는 문제다. revision·ready·예약 재생 취소 규칙과 단계 2 테스트로 다룬다.
- Safari 오디오 활성화는 사용자 클릭 안에서 처리하며, 실제 시작 대기와 분리한다. 실기기 확인 필요 항목이다.
- 렌더링 실패와 오래된 비동기 작업, 패널 열림 중 단축키, 범위 밖 이동, 메트로놈 공용 컴포넌트 변경을 각 담당 단계의 테스트에 포함했다.
- ‘적용’과 ‘다음 악보 기본값 저장’의 의미를 분리해 기존 저장 키·동작을 유지한다. 데이터 마이그레이션은 필요 없다.
- 구현 담당자는 한 명으로 유지하며 계획/코드 변경에 맞춰 이 문서의 체크박스를 갱신한다.
- 이번 계획 검토는 자체 검토다. 부모 실행 모델·추론 강도는 확인할 수 없어 선호 모델이 사용됐다고 표시하지 않는다.
