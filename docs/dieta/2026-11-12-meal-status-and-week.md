# 끼니 기록 상태, 추가 분석 미리보기, 최근 7일 돌아보기

1. 식사 화면에서 아침·점심·저녁 상태를 선택하거나 해제한다. 기록 완료에는 음식이나 평균 기록이 필요하다. 건너뜀과 기억 안 남은 빈 끼니에만 지정한다. 음식 변경으로 모순되는 상태를 지우고 음식·열량·분석 횟수와 상태를 분리한다. 오늘·어제만 수정하며 과거 날짜는 조회한다. 기존 날짜별 JSON 저장소를 사용한다.
2. 기본 분석 후 식사 화면의 마지막 분석 버튼 앞에 끼니별로 새 음식과 개수를 표시한다. 기존 큐의 추가 항목만 사용하며 음식 삭제 시 갱신한다. 상태 변경과 조회는 분석을 호출하지 않는다.
3. 홈의 최근 7일 기록에서 상세를 요청할 때만 끼니별 직접·평균·혼합 기록 일수와 건너뜀·기억 안 남을 계산한다. 세 날짜 이상 음식이 직접 기록된 끼니에서 같은 음식명이 두 날짜 이상 반복될 때 음식과 기록 일수를 보여준다. 하루 여러 번 기록한 음식은 하루로 센다.
4. DietaService와 일별 DTO, 날짜별 저장소, 컨트롤러, 식사·홈 컴포넌트와 API 타입을 확장한다. 상태 수정은 기존 사용자 잠금과 날짜 검사를 공유하고 이전 선택값 검증으로 타 기기 변경을 보호한다. 하루 평가에 상태를 반영하고 이후 변경 시 지난 분석 기준을 표시한다.
5. 상태와 음식 충돌, 추정/직접 구분, 표본 임계값, 추가분 필터, 과거 조회를 테스트한다. 모바일 320·390px에서 상태 선택, 추가 분석 대상 확인, 주간 상세 열기를 점검한다.

추가 분석 요청에는 화면에서 확인한 음식 ID를 보낸다. 서버가 사용자 잠금 안에서 최신 목록과 대조하여 다르면 남은 기회를 소비하기 전에 다시 조회하게 한다. 주간 열량 변화는 첫 3일과 마지막 3일에 각각 2일 이상 비교 가능한 분석값이 있을 때만 양쪽 표본 수와 평균을 표시한다.

활동과 식사 화면은 같은 날짜 선택기와 시간대·날짜 검증을 사용한다. 활동 목록은 날짜 전환 시 재사용하고 오래된 날짜에는 해당 날짜의 걸음, 개별 운동, 저장된 열량을 조회 전용으로 표시한다.
