# Dieta 오늘·어제 식사와 활동 간편 기록 계획

기억나는 내용만 남기고, 반복한 식사나 운동은 다시 입력할 필요가 없게 한다. 식사와 활동은 각각 직접 입력, 전날 기록 가져오기, 평소 수준으로 채우기를 지원한다. 구현 시 기존 [기능 명세](FEATURE_SPEC.md)와 [일일 분석 정책](2026-11-08-scheduled-meal-analysis.md)을 함께 적용한다.

## 화면과 저장 규칙

| 사용자의 선택 | 저장 동작 |
|---|---|
| 오늘 / 어제 | 선택한 날짜가 모든 입력의 대상이다. 서버가 프로필 예약 시간대 또는 기기 시간대를 기준으로 두 날짜를 정한다. 복사 화면에는 출발일과 도착일을 모두 쓴다. 어제를 편집하면 그 전날에서 가져올 수 있다. |
| 어제 식사 가져오기 | 끼니별로 음식과 등록 레시피를 보여준다. 먹은 항목만 골라 수량 또는 문구를 고친 뒤 저장한다. 한 줄 음식은 대상 날짜의 새 기록이 되고, 영양값이 있는 등록 레시피는 기존 섭취 추가 방식을 사용한다. 원본 날짜의 일일 합계나 분석 평가는 복사하지 않는다. |
| 자주 먹는 식사 | 기록한 끼니에서 원하는 음식과 등록 레시피를 골라 이름을 붙여 저장한다. 오늘 또는 어제 화면에서 식사 이름을 누르면 구성과 분량이 보인다. 그대로 추가하거나 이번에 먹은 항목만 조정한다. |
| 어제 운동 가져오기 | 활동명, 운동 시간, 걸음, 운동 소모 kcal 중 어제 실제로 기록한 항목을 선택한다. 저장 전 값을 수정할 수 있다. 오늘 직접 입력한 값은 유지하고 빈 항목부터 제안한다. |
| 평소 수준으로 채우기 | 선택한 날짜 **이전** 28일을 기본 조회 기간으로 제안한다. 식사는 같은 끼니의 영양 합계가 확인된 날짜, 활동은 각 지표의 값이 있는 날짜를 대상으로 각각 최소 3일일 때만 제안한다. 평균, 단위, 표본 일수를 먼저 보여준다. 수치 조정 후에도 추정 표시를 유지한다. |
| 기억 안 남 / 일부만 기억남 | 아무것도 저장하지 않아도 된다. 활동명만 저장할 수 있고 모르는 수치는 비워 둔다. ‘운동 안 함’은 명시한 운동 시간만 0분으로 기록한다. 걸음과 활동 kcal는 별도 값이다. |

사용자가 실제로 먹거나 수행했다고 확인한 복사는 직접 기록처럼 취급한다. 추정 기록은 복사 후보와 이후 평균 표본에서 제외한다. 미기록은 평균 분모에서 제외하고, 직접 입력한 0은 포함한다. 대상 끼니에 직접 기록이 하나라도 있으면 끼니 전체 평균을 더하지 않는다. 실제 음식이 들어오면 같은 끼니의 추정을 교체하고, 활동은 해당 지표만 교체한다.

## 활동 열량 입력 변경

걸음 수와 프로필 키, 기록일 이하 가장 최근 체중으로 기존 걸음 목표 공식의 역산값을 저장한다. 운동 열량은 직접 입력하고 활동 합계에는 걸음 추정과 운동 입력을 한 번씩 반영한다. 걸음과 겹치는 운동은 중복 입력을 피하도록 안내한다. 운동 시간으로 열량을 다시 더하지 않는다. 전날 복사와 평균 입력에서도 직접 입력할 수 있는 열량은 운동분이며, 걸음분은 대상 날짜 기준으로 계산한다. 과거 총량은 그대로 읽고 명시적으로 전환할 때만 새 방식으로 저장한다.

## 구현 및 검증 상태

아래 1~6단계의 기능을 저장소에 반영했다. 프런트엔드 Dieta 테스트 53개와 백엔드 단위 테스트 35개를 실행했고, Chrome의 390px·1280px 화면에서 전날 식사 저장과 활동 평균 선택을 모의 API로 확인했다. 운영 배포 전 남은 검증은 실제 MySQL·Redis 통합 테스트와 마이그레이션 실행이다. 이 환경에서는 Docker 엔진 소켓에 연결되지 않아 Testcontainers 테스트가 건너뛰어졌다.

## 구현 순서와 검증 기준

- [x] **1. 날짜와 저장 모델.** Spring Dieta 도메인, MySQL 초기화·운영 SQL·dev Flyway에 날짜별 식사 항목과 출처, 끼니별 영양값, 활동명과 지표별 출처를 저장할 구조를 추가한다. 사용자·날짜·원본 항목으로 복사 중복을 막는다. 기존 활동의 null은 유지한다. 기존 식사는 저장된 식사 스냅샷, 날짜별 섭취 레시피, 살아 있는 Redis 큐에서 중복을 제거해 읽는다. 일일 합계만 남은 과거 기록에서 음식이나 끼니별 수치를 만들어내지 않는다. 기존 DB 업그레이드·재실행과 Redis 만료 후 조회를 테스트한다.
- [x] **2. 후보 조회와 선택 저장.** DietaController에 대상 날짜별 간편 입력 후보 조회와 선택 적용 API를 추가한다. 인증된 사용자의 전날 기록 및 평균 후보만 서버에서 산출한다. DietaService에서 원본 ID와 대상 날짜를 재검증하고, 한 요청을 하나의 트랜잭션으로 적용한다. 같은 요청 재전송은 한 번만 반영한다. 그 사이 직접 기록이 바뀌면 새 미리보기를 요청한다. 다른 사용자 원본 접근, 전날 기록 없음, 일부 선택, 더블클릭, 날짜 경계를 검증한다.
- [x] **3. 식사 합계와 분석 횟수.** 현재 Gemini 응답은 한 줄 식사 전체의 총량이므로, 향후 분석부터 같은 호출에서 끼니별 영양값도 받아 검증·저장한다. 끼니별 수치가 누락되거나 합계와 맞지 않으면 기존 일일 결과는 유지하고 해당 분석의 끼니별 값을 평균에서 제외한다. 등록 레시피는 기존 영양값을 정확히 한 번 합산한다. 평균 입력이나 복사 저장 자체는 Gemini를 호출하지 않는다. 확인한 한 줄 음식만 기존 메인 1회·추가 1회 규칙에 들어간다. 기회 소진 후에는 기록만 저장하고 미반영 표시를 한다. 예약 처리 중 입력은 완료 후 다시 저장하게 하며 분석에 쓰인 스냅샷을 보호한다. 평균→직접 교체, 메인 뒤 복사, 추가 기회 소진, 레시피 중복 합산을 검증한다.
- [x] **4. 활동과 통계.** DietaActivityUpsertRequest, DietaActivityLog, DietaGeminiRequestBuilder와 주간 집계를 수정한다. 운동명만 있는 활동은 운동 횟수에 포함하고 분·kcal 평균에는 넣지 않는다. 운동 안 함과 운동을 같은 날 동시에 표시하지 않는다. 주간 화면에는 식사·활동의 기록 일수를 각각 표시하고 추정만 있는 날짜를 구분한다. AI 평가는 미기록 활동을 낮은 활동량으로 단정하지 않게 한다. 직접 입력한 0, null, 부분 기록, 추정값이 섞인 주를 검증한다.
- [x] **5. 자주 먹는 식사 저장·불러오기.** DietaMealsPage의 끼니별 목록에 ‘자주 먹는 식사로 저장’, 음식 입력 옆에 ‘자주 먹는 식사’를 둔다. 이름과 기본 끼니, 선택한 한 줄 음식의 문구·양, 등록 레시피의 1인분 영양값과 분량을 사용자별 MySQL 테이블에 보관한다. 평균 추정치와 일일 Gemini 합계는 저장 대상에서 제외한다. 저장 목록은 최근 사용순으로 보여주고 이름·구성 수정과 삭제를 지원한다. DietaController와 dietaApi에 본인 식사 목록 조회·저장·수정·삭제를 추가하고, 날짜별 적용은 2단계의 선택 저장 경로를 재사용한다. 한 번의 적용 요청은 한 번만 반영하되 다른 날짜나 끼니에는 같은 식사를 다시 쓸 수 있다. 불러올 때 바꾼 양은 그날에만 적용하고, 저장본 수정·삭제도 과거 기록에 영향을 주지 않는다. Gemini 호출 0회, 등록 레시피 영양값의 분량별 합산, 일부 항목 제외, 다른 사용자 접근 거절, 중복 전송을 검증한다.
- [x] **6. 화면과 배포.** DietaMealsPage와 DietaActivityPage에 날짜 선택, 출발일→도착일 미리보기, 선택·수정·저장, 추정 표시를 추가한다. DietaHomePage와 주간 요약도 같은 출처·합계 규칙을 사용한다. dietaApi와 dietaMappers에 날짜 및 출처 계약을 반영한다. 모바일·데스크톱에서 어제 편집 중 자정 통과, 뒤로 가기, 저장 실패 후 재시도, 취소 시 무변경을 검증한다. MySQL·Redis 통합 테스트와 모의 Gemini 호출 수 검증을 거친 뒤 DB → 백엔드 → 프런트엔드 순으로 배포한다.

**완료 예시** 사용자가 오늘 아침과 걸음 수를 직접 기록한 뒤 어제 저녁 메뉴와 어제 운동 시간만 복사한다. 오늘 아침과 걸음 수는 유지되고 새 값은 한 번씩만 저장된다. 어제 기록도 그대로다. 기억나지 않는 점심은 표본이 충분하면 평균 추정으로 채울 수 있고, 나중에 실제 점심을 입력하면 추정이 빠진다.
